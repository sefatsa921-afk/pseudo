# Veya API contract

These operations are the boundary between the mobile shell and a future backend. Names are provider-neutral; Supabase RPCs/queries or a custom API may implement them.

## Session and profile

- `POST /auth/sign-in` — authenticate a user through the chosen identity provider.
- `GET /me` — return the public profile, role, scoped memberships, and active representative modules.
- `PATCH /me/profile` — update approved public profile fields only.
- `POST /auth/sign-out` — revoke the local session.

## Communities and feed

- `GET /communities?followed=true` — list followed pages/communities.
- `POST /communities/{id}/follow` and `DELETE /communities/{id}/follow` — explicit notification/feed subscription.
- `GET /feed?tab=posts|replies|reels` — return content with source type, verified/sponsored labels, and visibility already checked.
- `POST /posts`, `POST /posts/{id}/comments`, and `POST /posts/{id}/reactions` — create interactions only when the account is allowed to do so.

## Scoped verification

- `POST /verification/sessions` — administrator creates a short-lived, single-use session for one residence/community. The raw token is shown only through the QR display flow; the server stores a hash.
- `POST /verification/requests` — student submits a scan result for the same scope. The server checks expiry, single-use state, residence/community scope, and requester identity.
- `GET /verification/requests?mine=true` — student sees their own pending/approved/rejected requests.
- `POST /verification/requests/{id}/approve` or `/reject` — authorised administrator reviews the request and creates the scoped membership/badge only on approval.

## Friendship and messages

- `POST /friend-requests`, `POST /friend-requests/{id}/accept`, and `/decline` — explicit friendship workflow.
- `GET /messages/{peer}` — allowed only for an accepted friend or an authorised module-representative/lecturer pair.
- `POST /messages/{peer}` — the same rule is checked again server-side; the UI is not the security boundary.

## Notifications

- `GET /notifications` — returns only notifications generated by followed pages/communities or direct account events.
- `POST /notification-subscriptions` and `DELETE /notification-subscriptions/{id}` — manage scoped subscriptions.
- `POST /device-tokens` — register a push token after authentication; tokens must be encrypted/secured and removable.

## Administrative controls

- `GET /admin/verification-queue` — scoped to the administrator's authorised residence/community.
- `POST /admin/audit-events` — normally written by trusted server functions, not accepted as arbitrary client data.
- `GET /admin/reports` and moderation actions — restricted by role and community scope.

## Error contract

Return a stable JSON shape:

```json
{
  "error": {
    "code": "VERIFICATION_SESSION_EXPIRED",
    "message": "This verification QR has expired. Ask the administrator to create a new one."
  }
}
```

The mobile shell should keep the demo fallback available when the backend is not configured and should never imply that a failed network request completed a real action.

## Server functions added in schema v2 (Supabase `/rpc/<name>`)

| Function | Who | Purpose |
| --- | --- | --- |
| `create_verification_session(p_community, p_ttl_minutes, p_max_uses)` | community admin | returns the one-time QR payload `veya:v1:<token>`; only a hash is stored |
| `submit_verification_request(p_token)` | student | validates token, expiry, use count; creates a *pending* request |
| `review_verification_request(p_request, p_approve)` | community admin | approves/rejects; approval creates membership + credential |
| `review_post_media(p_media, p_approve, p_note)` | staff / community admin | media approval state |
| `review_event`, `review_opportunity`, `decide_booking` | admins / staff / host | approvals; `review_opportunity` sets the trust label |
| `moderate_content(p_target_type, p_target, p_new_state, p_note)` | staff / community admin | hide, remove or restore a post or comment |
| `resolve_report`, `suspend_user` | staff / community admin | close reports, suspend accounts |
| `create_portfolio_share`, `read_shared_portfolio` | student / signed-in viewer | time-limited share of chosen items only |
| `set_user_role`, `grant_community_admin` | admin | the only way roles and admin memberships change |

Reports and blocks use plain table inserts (`reports`, `user_blocks`); `reporter_id` / `blocker_id` default to the caller.
